# 👁️ Documentos de Visión
## 🌈 Academia Gloria Valentina

Esta carpeta conserva la **visión, intención y filosofía** que ayudan a explicar hacia dónde quiere crecer la Academia.

Los documentos de `docs/vision/`:

- expresan propósito y dirección;
- pueden describir capacidades aspiracionales;
- no sustituyen estándares, especificaciones, modelos activos ni diseño de producto;
- no demuestran por sí solos que una funcionalidad esté implementada;
- deben interpretarse junto con las fuentes propietarias vigentes.

## 🧭 Regla de lectura

> **La visión inspira; las fuentes propietarias gobiernan; el producto real confirma el estado implementado.**

Cuando una visión y una fuente normativa o el producto real difieran sobre el estado actual, prevalece la fuente propietaria vigente y la evidencia del repositorio.

## 🗃️ Fuentes históricas / sustituidas

- `06_IDENTIDAD_VISUAL_DE_LA_ACADEMIA.md` → histórico; hoy gobierna `docs/product/PRODUCT_IDENTIDAD_VISUAL_Y_PERSONAJES.md`;
- `MODELO-USUARIOS_ALUMNOS_Y_ROLES.md` → histórico; hoy gobiernan `docs/models/MODELO_ROLES.md`, `docs/standards/STD-USUARIOS_ROLES_Y_ACCESOS.md` y la referencia técnica vigente de Usuarios/Firestore.

Las rutas anteriores pueden conservar un puntero mínimo de compatibilidad para evitar referencias rotas, pero ese puntero no convierte el contenido histórico en fuente activa.

## 🔗 Fuentes de gobierno relacionadas

Antes de utilizar una visión para tomar una decisión de producto, contrastar según corresponda con:

- `docs/FOUNDATION.md`;

- `docs/product/PRODUCT_EXPERIENCE_ARCHITECTURE.md`;
- `docs/product/PRODUCT_IDENTIDAD_VISUAL_Y_PERSONAJES.md`;
- `docs/models/`;
- `docs/standards/`;

- y el código/comportamiento real.

## ✅ Regla práctica

Una visión puede decir **“queremos llegar aquí”**.

Un estándar o especificación debe decir **“esto es lo que gobierna ahora”**.

El repositorio y la validación funcional permiten confirmar **“esto es lo que realmente existe”**.
